# generic-mail

One process. It serves IMAP for objects already in a bucket, and authenticated SMTP that hands the raw message to Amazon SES.

INBOX is the inbound prefix. Those objects are never rewritten. Expunging Trash requests deletion of the original S3 object. If INBOX or an imported mailbox still reads that object directly, deletion waits until its last S3 reference is removed. Local copies remain readable. Deletion requests live in SQLite and retry during inbound sync after an AWS failure or process restart. Expunging other folders does not request S3 deletion. The AWS role needs `s3:DeleteObject` for the relevant mail prefixes; versioned buckets retain historical versions according to their S3 policy. On an empty local database the process imports `imap-state/mailboxes.json` once, including UIDs, UID validity, flags, and skipped keys, and does not write that object back. After that, flags, folders, and UIDs live in SQLite on `MAIL_DATA` (default `/var/lib/generic-mail`). Copying or appending into any mailbox other than INBOX writes the body as a file on that volume. Losing the volume drops local state and forces clients to resync; the inbound objects remain in the bucket.

Message bodies are cached in the process (64 MiB). The first fetch reads the bucket or the local file. Later fetches in that process do not.

SMTP is AUTH PLAIN after TLS. Envelope senders default to the login address. Set comma-separated `MAIL_ALLOWED_FROM` for extra addresses or `MAIL_ALLOWED_FROM_DOMAINS` for whole domains (chart values `mailbox.allowedFrom` and `mailbox.allowedFromDomains`). To retain the previous implicit domain permission, explicitly configure `generic.business` in the domain list. Temporary delivery failures return SMTP 451 so clients can retry. Ports are IMAPS 993, submission 587, and SMTPS 465. The AWS SDK uses its default credential chain, including a projected service-account token when `AWS_ROLE_ARN` and `AWS_WEB_IDENTITY_TOKEN_FILE` are set.

When `OAUTH_JWKS_URL` is set, IMAP and submission also advertise `XOAUTH2` and `OAUTHBEARER`. The initial response is the one Roundcube sends: the SASL username is an allowed identity, and `auth=` is an RS256 access token (a `Bearer ` prefix is optional). The token issuer, audience, and either `preferred_username` or `email` must match `OAUTH_ISSUER`, `OAUTH_AUDIENCE`, and `OAUTH_ALLOWED`. Password login is unchanged.

Required environment: `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_HOSTNAME`, `S3_BUCKET`. `MAIL_DATA` is the writable directory for the SQLite index and local message files.

The chart defaults are generic. A cluster sets the bucket, hostname, role, and image in its own values.

Retention belongs in S3 configuration. With [S3 Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeletingObjectVersions.html) enabled, the gateway's ordinary `DeleteObject` call creates a delete marker; it does not erase historical versions. Configure noncurrent-version lifecycle rules for the desired recovery window. For enforced retention periods or legal holds, use [S3 Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html). Locked versions remain protected even when a delete marker hides the message from normal mailbox access. The gateway never specifies a version ID or requests a retention bypass, and its role does not need `s3:DeleteObjectVersion` or retention-bypass permissions. This chart does not configure bucket versioning, lifecycle, or Object Lock.
